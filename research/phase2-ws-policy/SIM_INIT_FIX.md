# SIM_INIT_FIX — belady_same_state_prewarm init correction

Fix branch `fix/phase2-ws-sim-init`, base `95dfe0d`.

## What was wrong

`tools/phase2_ws_policy_sim_v4.py` `BeladyPrewarm.__init__` initialized every
prewarmed resident entry's next-use distance to `10**12` ("never used
again"):

```python
self.resident = {k: 10 ** 12 for k in init}
```

Under that init the first real faults always evicted a prewarmed entry
(every resident tied at the maximum distance), so soon-needed prewarmed
records were dropped before their first use — understating the regime-C
bound `belady_same_state_prewarm` (contract C2, fetch-on-fault MIN given
the same initial state).

## The fix

Init-only change. `simulate()` now computes `first_use` (first occurrence
index of each record in the scope stream) and passes it to the cache
constructor; `BeladyPrewarm` initializes resident distances to the exact
first-future-use:

```python
self.resident = {k: fu.get(k, 10 ** 12) for k in init}
```

(`10**12` remains only for records that never occur in the stream.)
Identical semantics to the independent reference implementation
`tools/phase2_regime_c_eval.py` (`c2_min_misses(exact_init=True)`,
research/phase2-regime-c @ 643d3559). Policy logic (`touch`) untouched.
