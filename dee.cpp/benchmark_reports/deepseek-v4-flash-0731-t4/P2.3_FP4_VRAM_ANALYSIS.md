# P2.3 — Packed FP4 VRAM Residency: Analysis

Status: packed-device repair rerun **v47 is active** on exact 2x Tesla T4 at
commit `3178542`. v45 was `REJECT_NUMERICAL`; v46 was `INVALID_EXPERIMENT`
at its admission test. No packed-FP4 performance result is accepted yet.

## What P2.3 adds

`DeviceCacheDType::Fp4E2m1` — the VRAM expert cache stores the checkpoint's
**packed e2m1fn bytes + e8m0 scales verbatim** (12.75 MiB per real expert)
instead of the expanded FP16 blob (48 MiB). Expansion happens only at compute
time, into one bounded per-engine FP16 scratch, using the same
`fp4_e2m1_to_f16_cuda` kernel as the old transfer-stream path — so the FP16
values (and therefore tokens) are unchanged while the cache holds **3.76× more
resident experts per GiB**.

Wiring: `stage_expert` streams packed bytes via `prefetch_fp4_regions_packed`;
compute decodes via `decode_fp4_cache_block_to_scratch` in
`moe_forward_experts`, `moe_forward_batch_device`, and `forward_layer_cuda`.
Combined/pointer-batched paths fail closed on Fp16. Harness knob:
`NATIVE_CACHE_DTYPE=fp4`.

## Corrected trace replay (sealed DS10 v12 token trace)

The replay now matches the live scheduler geometry: duplicate prefill expert
IDs are grouped once per layer, cuda0/cuda1 have independent caches split at
layer 22, and shared experts are excluded because they use a separate
persistent torch path. Both residency modes transfer the same 12.75 MiB
packed FP4 record on a miss; FP16 residency expands it on GPU.

The corrected trace contains 5,101 staged routed requests (2,615/2,486).

## Roofline status

The earlier table mixed projected hit rates, nominal storage bandwidth, and a
component compute estimate. It is withdrawn as an acceptance artifact. The
DEE4 profiling run records live bytes/token, source-read wall, H2D event time,
and routed compute time; only those measured quantities will establish the
next roofline.

## Conclusion

1. Packed FP4 provides a proven **3.76x capacity geometry**, not yet a proven
   end-to-end speedup.
2. It changes residency, not the miss-transfer representation or arithmetic.
3. v45 proved the live device-batch seam had a correctness risk that component
   tests missed. v47 must pass the exact 16-token contract before this mode is
   accepted or made default.
