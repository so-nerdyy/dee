## Conclusion

1. FP4 VRAM cache is a **3.76× capacity improvement** but alone delivers only marginal throughput gains because the storage path still dominates (95%+ of wall clock).

2. **At 126 MB/s** (local SSD), even with perfect VRAM cache (100% hit), throughput is capped at 0.30 tok/s by GPU compute alone.

3. **To reach 0.5+ tok/s** requires ALL of:
   - DEE4 contiguous repack (P2.2) → ~10× faster storage reads
   - Packed FP4 VRAM cache (P2.3) → fewer reads needed
   - Router-ahead prefetch (P2.8) → overlap I/O with compute
   - FP4 tile-decode GEMV (P2.5) → reduce GPU compute from 3.35s

4. **The P2.3 implementation** should add a `DeviceCacheDType::Fp4E2m1` mode that stores packed FP4 in the VRAM arena, with a separate dequantization kernel called at compute time. This requires changes to `VramCacheManager` (trivial — it's just `nbytes`), `AsyncPrefetcher` (transfer packed bytes), and a new `dequantize_fp4_expert_cuda` kernel.
